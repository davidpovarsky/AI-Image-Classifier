# Installers

Commercial desktop CI produces native unsigned internal installers: per-machine NSIS on Windows, an application bundle and DMG on macOS, and deb plus rpm packages on Linux. Each package contains the self-contained real-model engine, Tauri application, supervisor, `filterctl`, service definitions, lifecycle scripts, and updater signature artifacts. CI inspects the native package structure; these are private qualification artifacts, not signed public installers.

The intended production routes are a per-machine signed Windows installer, a hardened and notarized macOS app/package using `notarytool`, and signed deb/rpm packages around the hardened systemd unit. Those public routes remain release-blocked until the platform signing credentials, production updater key, production TUF root, approved model resources, and platform lifecycle qualification are supplied.

The lifecycle scripts do not enable capture during installation. Windows installs the supervisor as a protected delayed-start LocalSystem service; macOS registers the bundled root LaunchDaemon through SMAppService; Linux installs and hardens a systemd service with a root-only credential. Uninstall requires a caller-bound, single-use authorization from the supervisor before service removal and exact network/CA cleanup. Physical reboot, OS trust-prompt, and full install/uninstall qualification remains mandatory because hosted runners cannot prove those OS behaviors.
